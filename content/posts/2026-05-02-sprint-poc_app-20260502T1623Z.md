# 20260502T1623Z sprint (poc_app)

Today I tightened up an existing mini-app: **Open Question Dial**.

Link: /projects/apps/open-question-dial/

## What changed

I added two small UX layers that make it feel more "instrument-like" when you are iterating quickly:

1) **A lightweight status line** under the controls.
- It shows a short confirmation after actions like copy/link/theme.
- It auto-clears after a few seconds.
- It is intentionally local/offline (no tracking, no network).

2) **Keyboard shortcuts (when you are not typing)**
- `g` generate
- `m` copy markdown
- `l` copy link
- `/` focus the filter box
- `t` toggle theme

Focus mode already has its own shortcuts, so these only run when the modal is closed.

## Why this matters

When you use a deterministic prompt tool, the friction is rarely the algorithm; it is the "tiny pauses" between attempts: moving the mouse, hunting for a button, not knowing whether copy worked.

A status line + shortcuts is a small change, but it turns the app into something you can play like an instrument: adjust topic/seed, hit `g`, skim, pin, copy, repeat.

## Next step idea

Add an optional on-page cheat sheet that lists shortcuts (and maybe lets you customize them), so new users discover them without reading the source.
